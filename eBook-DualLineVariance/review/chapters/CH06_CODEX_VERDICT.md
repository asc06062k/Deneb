## การตัดสินประเด็น overclaim

1. **เส้นขอบประใน Step 2 มองยาก — ยอมรับได้ ไม่ต้องแก้ spec**

   คำอธิบายตรงกับภาพจริง: border อยู่ตำแหน่งเดียวกับ Actual/Reference จึงถูกชั้นเส้นด้านหน้าบังเป็นส่วนใหญ่ ภาพ 6-3 ทำให้ผลของ Step มองเห็นและไม่ได้สร้างผลลัพธ์ที่เกินจากสเปก การคง final spec สำคัญกว่าการเพิ่มความหนาเพื่อภาพสาธิต

2. **`detail: Segment_ID` — คำอธิบายถูกต้อง**

   เอกสาร Vega-Lite ระบุว่า `detail` เพิ่ม grouping field ให้ line/area โดยไม่ผูกกับ visual property ดังนั้นข้อความว่าใช้แยกรูปพื้นที่ตาม `Segment_ID` ถูกต้องสำหรับชุดข้อมูลนี้ แม้ผู้เขียนยังไม่ได้ทดลองถอดออกจริง ([Vega-Lite Encoding](https://vega.github.io/vega-lite/docs/encoding.html), [Area mark](https://vega.github.io/vega-lite/docs/area.html))

3. **ผลต่างศูนย์เดือนมิถุนายน — ถูกต้อง**

   Connector ใช้เงื่อนไข strict จึงเข้าฝั่ง Bad แต่ `y == y2` ทำให้มีความยาวศูนย์และมองไม่เห็น ส่วนพื้นที่สองข้างของเดือนมิถุนายนใช้ `Run_Sign` ของแต่ละ segment จึงเป็น พ.ค.–มิ.ย. Good และ มิ.ย.–ก.ค. Bad ตามที่เขียน

4. **Step 4 — ระดับหลักฐานเพียงพอ**

   - การสลับสีมีหลักฐานจากภาพ 6-5/6-6
   - เส้นขอบประ Bad ใน Lower is Good แม้ไม่เห็นชัดในภาพ แต่ยืนยันได้จาก filter ในสเปก จึงไม่ใช่ overclaim เมื่อบทบอกชัดว่าอ่านจากเงื่อนไข
   - fallback เป็น Higher is Good ตรงกับโค้ด Power Query แต่การระบุว่ายังไม่ผ่าน Power Query edge-case test และจะตรวจในบทที่ 9 เหมาะสม
   - การลบ Applied Step ด้วยปุ่ม ✕ เป็นขั้นตอน UI ปกติและปุ่มปรากฏในภาพ 6-5 การไม่มีภาพหลังคืนค่าไม่ใช่ blocker เพราะมี checkpoint ย้ำทั้งท้าย Step และท้ายบท

5. **แบบฝึกหัดที่ยังไม่ได้ลอง — ยอมรับได้**

   การแก้ opacity, `strokeWidth` และความหนา Connector เป็นการแก้ property ตรงไปตรงมา อีกทั้งบทระบุสถานะที่ยังไม่ได้ลองไว้ ไม่ได้อ้างว่าได้ทดสอบแล้ว

6. **คำแนะนำให้ลบ `interpolate: monotone` — อยู่ในบทได้**

   ไม่ขัดกับคำตัดสินให้คงเส้นโค้ง เพราะนำเสนอเป็นทางเลือกสำหรับผู้อ่านที่ให้ความสำคัญกับการตรงกันของเส้นและขอบพื้นที่ และระบุชัดว่ายังไม่ได้ทดลองใน Deneb จริง กล่อง M-11 ตรงกับ [PROJECT_PLAN.md](/D:/DATA/Deneb/eBook-DualLineVariance/PROJECT_PLAN.md:230) และคำอธิบายในบทก่อนหน้า

7. **ไม่มีภาพ Report view — ไม่เป็น Mandatory**

   กฎภาพกำหนดว่าภาพ UI ต้องมาจากระบบจริงและ caption ต้องตรง ไม่ได้กำหนดว่าทุกบทต้องมี Report view ภาพ Editor ปัจจุบันแสดงผล chart ใน Preview พร้อมข้อมูล Source ซึ่งเพียงพอสำหรับตรวจ Step ทางเทคนิค

## Optional improvements

- ในคำอธิบาย `detail` อาจปรับให้แม่นทางศัพท์ขึ้นเล็กน้อยเป็น: “เพิ่ม `Segment_ID` เป็น grouping field โดยไม่เข้ารหัสเป็นสีหรือรูปร่าง ทำให้ข้อมูลชุดนี้สร้าง area แยกต่อ segment”
- ใกล้คำแนะนำลบ `interpolate: monotone` อาจเพิ่มว่าเป็น “ทางเลือก ไม่ใช่ค่าที่ Workshop แนะนำ” เพื่อกันผู้อ่านเข้าใจว่าต้องย้อนคำตัดสินการออกแบบ
- Step 4 อาจเพิ่มประโยคว่า “ถ้าปิด Power Query ไปแล้ว ให้เปิดกลับมาตรวจว่า Applied Steps เหลือถึง `Changed Type`” เป็นจุดตรวจสำรองสำหรับการคืนค่า
- หาก Phase 4 มีพื้นที่หน้าเหลือ การเพิ่ม Report view หลัง Step 4 จะช่วยให้ผู้อ่านเห็นผลในขนาด Visual จริง แต่เป็นงานเสริม ไม่ใช่เงื่อนไขผ่าน
- ภาพ 6-3 ไม่ขัดกฎ “ห้ามวาดจากการคาดเดา UI” เพราะใช้พิกเซลจริงจากภาพ 6-1/6-2 และเปิดเผยว่าเป็นภาพตัด–ขยายแล้ว แนะนำให้คงคำว่า “nearest-neighbor” และคำชี้แจงต้นบทไว้

## คำถามที่ต้องรอหลักฐานจากผู้ใช้

ไม่มีคำถามที่ขวางการ `PASS` ประเด็นที่ยังไม่ได้ทดลองจริง—แบบฝึกหัด, fallback edge case, การคืนค่าหลังลบ Applied Step และทางเลือกตัด `monotone`—ถูกจำกัดขอบเขตและเปิดเผยสถานะไว้อย่างเหมาะสมแล้ว ไม่ได้ถูกนำเสนอเป็นผลทดสอบจริง.
